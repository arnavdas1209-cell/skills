Version: 2.0.5

A specialized figure-making skill generated by this factory must be self-contained, publishable, and reusable for arbitrary target papers of the same figure class.

## Required Generated Workflow

Generated skills must include this production workflow or a stricter domain-specific equivalent:

| Step | Mode | Required Meaning |
|---|---|---|
| P1 | TEXT_ONLY | Startup/intake material, optional references, and display saved subtype atlas with Markdown image embeds when available |
| P2 | TEXT_ONLY | Diagnose figure need and subtype routing, displaying relevant saved atlas images with Markdown image embeds |
| P3 | TEXT_ONLY | Produce 4-6 text candidates, normally 6, and display saved style/layout boards with Markdown image embeds when style or layout is discussed |
| P4 | TEXT_ONLY | Set up the visual candidate board |
| P5 | IMAGE_ONLY | Generate/display 4-6 diverse first-round candidate images or schematic candidates, normally 6 |
| P6 | TEXT_ONLY | Record first-round image batch, compare candidates, and select the strongest current direction |
| P6b | TEXT_ONLY | Set up 4-6 paper-local best-practice optimization axes, normally 6, around the first-round winner |
| P6b-IMAGE | IMAGE_ONLY | Generate/display 4-6 second-round target-paper variants, normally 6 |
| P6c | TEXT_ONLY | Record second-round batch, compare variants, and lock the final direction |
| P7 | TEXT_ONLY | Build final image brief/prompt only after P6c |
| P8 | IMAGE_ONLY | Generate formal figure candidate or revision batch |
| P9 | TEXT_ONLY | Review, caption, legend, body text, and handoff |

P4/P5/P6 are mandatory for the diverse first-round direction-setting bridge. P6b/P6b-IMAGE/P6c are mandatory for paper-local best-practice optimization before final prompt construction.

## Required Content

The generated skill must include:

- first-trigger startup gate;
- saved subtype/style illustration atlas in `assets/subtype-atlas/`;
- startup display of all available saved subtype atlas boards with renderable Markdown image embeds;
- text-turn display of relevant saved subtype/layout/style/density boards or non-target concept/modeling example images with renderable Markdown image embeds when abstract visual decisions are discussed;
- visual-structure-as-image behavior: generated skills must not describe visual structure, layout skeleton, panel choreography, module topology, arrow grammar, candidate-board structure, second-round optimization geometry, or final content architecture with prose/bullets only; they must embed a saved reference or non-target visual-structure concept/modeling image when technically possible;
- visible plan in every text reply;
- current state/output footer in every text reply;
- all steps and current position in every text footer;
- final next-question help in every text reply, including the unknown-next prompt;
- target-paper image isolation with inline non-target reference display;
- explicit response mode on every step;
- default recommendation when presenting multiple options;
- 4-6 text candidates, normally 6;
- 4-6 first-round image candidates, normally 6, maximizing direction-level diversity;
- 4-6 second-round image variants, normally 6, optimizing selected directions around paper-local details;
- mandatory visual-candidate setup -> image-only candidate generation -> candidate-review -> best-practice divergence setup -> image-only second-round generation -> second-round review bridge after multi-option text;
- required embedding of non-target concept diagrams, visual-structure examples, or skill-modeling example images in text replies for abstract visual decisions and visual-structure explanation, while forbidding target-paper candidate/final images in text replies;
- optional sample/reference-image protocol with multiple images and per-image attribute preferences;
- rendering route: ChatGPT web Create image through ChatGPT Images 2.0; Codex `$imagegen` first; if unavailable, ChatGPT Images 2.0 API or another approved image-generation API;
- prohibition against SVG, Mermaid, TikZ, Graphviz, HTML/CSS, canvas, plotting-library exports, filesystem/code-drawn images, or code-rendered visual candidates/drafts/finals/fallbacks;
- lawful source/corpus provenance if the skill depends on a corpus;
- full-feasible-corpus coverage notes when local PDFs or a paper index were available;
- multi-label evidence coverage when figures/PDFs can belong to multiple taxonomy classes;
- visual communication art style taxonomy and atlas coverage;
- release checklist with candidate-bridge tests.

## Required Subtype/Style Atlas

Production-grade generated skills must include:

- `assets/subtype-atlas/manifest.json`;
- `assets/subtype-atlas/boards/`;
- `assets/subtype-atlas/thumbnails/`;
- `references/subtype-illustration-atlas.md`.

The atlas must cover at least these classification angles: reader question, narrative role, logical gap, visual rhetoric, visual grammar/layout, paper slot, density/detail level, and visual communication art style.

Each board should combine multiple subtype illustrations where possible and visibly label subtype names. If there are many subtypes, use hierarchical boards: one overview board plus per-angle boards.

`manifest.json` must record asset id, classification angle, subtype, image path, thumbnail path, board path, generation route, build time or build id, intended use, transferable visual attributes, and limitations.

Saved atlas images must be embedded in `TEXT_ONLY` replies when available and relevant because they are reference display, not target-paper generation. When a text turn explains or compares subtype, layout grammar, visual style, density, metaphor, modeling pattern, candidate scheme differences, or final content architecture, it must embed a relevant saved reference or non-target concept/modeling example image, or record the missing asset plus repair action. When a text turn explains visual structure, layout skeleton, panel choreography, module topology, arrow grammar, candidate-board structure, second-round optimization geometry, or final content architecture, it must embed a saved reference or non-target visual-structure concept/modeling image; prose, bullets, ASCII, Mermaid, SVG, or code-rendered sketches are not sufficient as the only structure representation. Target-paper candidate/final generation remains `IMAGE_ONLY`. Display means real Markdown image syntax such as `![Subtype atlas](assets/subtype-atlas/boards/subtype-overview.png)`, or an absolute filesystem path version in Codex. A plain path list is not a valid display.

## Minimum Validation Tests

Before locking the specialized skill, run or simulate:

1. First-trigger startup response.
2. First-trigger image request boundary: the first reply remains text-only.
3. State-footer completeness after a text turn.
4. Automatic current-status/current-output listing.
5. Default recommendation after multiple figure schemes.
6. Text candidate turn with 4-6 candidates, normally 6.
7. Candidate bridge setup: after text candidates, the next step is visual candidate-board setup, not final prompt/final image/caption.
8. `IMAGE_ONLY` candidate-board generation with 4-6 candidates, normally 6.
9. Candidate-review turn records the previous image batch and selects a current best first-round direction.
10. P6 does not enter P7 directly; it triggers P6b best-practice divergence.
11. P6b text setup defines 4-6 paper-local optimization axes, normally 6, and displays a required saved reference or non-target concept/modeling example image when explaining the optimization grammar.
12. P6b-IMAGE generates 4-6 second-round target-paper variants, normally 6, with `second_round_candidate_batch_id`.
13. P6c records the second-round batch and locks `selected_second_round_candidate`.
14. Formal prompt construction after second-round direction lock.
15. Formal `IMAGE_ONLY` figure generation boundary.
16. Caption/body-text package output.
17. Optional reference-image handling.
18. Corpus coverage and evidence-lineage checks.
19. Saved subtype/style atlas exists with manifest, boards, thumbnails, and reference doc.
20. Startup reply displays available saved atlas boards with Markdown image embeds without target-paper image generation.
21. Text reply that discusses subtype/layout/style/density/metaphor/modeling/candidate differences/final content architecture displays a relevant saved or non-target concept/example image with Markdown syntax, or records the missing asset and suggests repair.
22. Text reply that explains visual structure/layout skeleton/panel choreography/module topology/arrow grammar/candidate-board structure/second-round optimization geometry/content architecture displays a relevant saved or non-target visual-structure image with Markdown syntax, or records the missing asset and repair action.
23. Text reply that displays saved atlas images does not produce target-paper candidate/final images in the same turn.
24. Text reply fails validation if it embeds target-paper candidate, draft, final, or revision images.

Fail validation if any example, starter message, or workflow lets the user go from text candidates directly to final prompt, final image generation, or caption without a candidate-image board, unless it explicitly records a user-requested text-only skip.

Fail validation if P6 selects a first-round candidate and then moves directly to P7/P8 without P6b/P6b-IMAGE/P6c, unless it records an explicit user override as a nonstandard limitation.

Fail validation if the generated skill lacks a saved subtype/style atlas, lacks startup atlas Markdown image embeds, only lists atlas paths, describes visual structure with prose/bullets only, embeds target-paper candidate/final images in a prose reply, treats non-target concept/example images as satisfying the candidate-image bridge, or uses a concept/example image as `second_round_candidate_batch_id`.
